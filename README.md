# Динамические группы муниципалитетов СберИндекса

Месячные расходы → потребительские признаки → сеть экономического сходства → спектральные группы → переходы и экономическая интерпретация.

На исходной панели из 1774 МО выбраны **три группы**. Число групп, масштабирование и сглаживание выбираются по 2023; результаты проверяются на 2024. Две группы устойчивее, четыре и более не проходят заданные требования. Экономические показатели не участвуют в построении графов.

- [Ноутбук с методикой и результатами](solution.ipynb)

## Быстрый запуск

Проверено на Python 3.13. После клонирования репозитория запускайте команды из корня проекта.

### Получение данных

Скачайте [data-v1.zip из релиза v1.0.0](https://github.com/the-romantic-dev/sber_index_2026/releases/download/v1.0.0/data-v1.zip) (около 7,8 МБ) и распакуйте **в корень проекта**. Архив уже содержит папку `data/`: при распаковке в неё получится лишний уровень `data/data/`. [Страница релиза](https://github.com/the-romantic-dev/sber_index_2026/releases/tag/v1.0.0).

В Windows скачивание и распаковку можно выполнить в PowerShell:

```powershell
$dataArchive = Join-Path $env:TEMP 'sber-index-data-v1.zip'
Invoke-WebRequest -Uri 'https://github.com/the-romantic-dev/sber_index_2026/releases/download/v1.0.0/data-v1.zip' -OutFile $dataArchive
Expand-Archive -LiteralPath $dataArchive -DestinationPath . -Force
```

В Linux/macOS:

```bash
curl -fL 'https://github.com/the-romantic-dev/sber_index_2026/releases/download/v1.0.0/data-v1.zip' -o /tmp/sber-index-data-v1.zip
unzip -o /tmp/sber-index-data-v1.zip -d .
```

Повторная распаковка заменяет одноимённые файлы в `data/`. Правильная структура после распаковки:

```text
config.json
solution/
data/
  raw/sberindex/consumption.parquet
  processed/municipalities/mo.parquet
  processed/municipal_geometry/teammate_data_map.json
  processed/economic_features/...
```

Состав входов и их назначение описаны в [data/README.md](data/README.md). Данные, архив исследований и генерируемые результаты исключены из Git. После получения архива расчёт использует только локальные файлы.

### Запуск расчёта

В Windows не требуется активация окружения:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m solution --config config.json
```

В Linux/macOS используйте `python3.13 -m venv .venv` и `.venv/bin/python` в следующих командах.

После запуска откройте `notebook_results/atlas.html`: это автономный **интерактивный атлас** за январь 2023 — декабрь 2024. Один ползунок одновременно меняет граф сходства, PCA и t-SNE; переключатель K использует все рассчитанные варианты числа групп (по умолчанию 2–10). Ниже показаны все 23 перехода и таблица выбранного перехода с цветами исходных и новых групп. Карта, поиск и карточка муниципалитета доступны в том же интерфейсе. Результаты, экономические описания и методика раскрываются внизу. Файл работает без сервера и внешних библиотек.

PCA использует общий базис, обученный на 2023; t-SNE рассчитан совместно для всех месячных наблюдений и служит ретроспективной визуализацией. Проекции не меняются при выборе K. Промежуточные кадры — интерполяция между наблюдаемыми месяцами. Полный t-SNE может увеличить время первого запуска; `notebook_results/atlas_projections.npz` кэширует проекции и автоматически пересчитывается при изменении признаков, seed или версии scikit-learn. Число соседей 12 относится к исходному kNN: после симметризации у узла может быть больше связей. При исчезновении группы согласование может назначить новой группе новый номер; K — число присутствующих групп в каждом месяце.

Для ноутбука:

```powershell
.\.venv\Scripts\python.exe -m jupyterlab solution.ipynb
```

Выберите окружение проекта и выполните **Restart Kernel and Run All Cells**. Ноутбук вызывает те же модули, что и командный запуск; второй реализации алгоритма в нём нет.

## Структура

```text
config.json          гиперпараметры и пути
requirements.txt     версии зависимостей
solution/            вычисления и создание материалов
  templates/         HTML, CSS и JavaScript презентации
solution.ipynb       методика и просмотр результатов
docs/                краткий отчёт, требования, описание СберИндекса
data/                локальные входы и реестр источников
tests/               короткие тесты и контрольные назначения
notebook_results/    результаты запуска, создаются автоматически
archive/             прежние исследования и версии, в расчёте не используется
```

| Модуль | Ответственность |
|---|---|
| `data.py` | Загрузка панели и справочника МО |
| `features.py` | Региональная нормировка, robust scaling, выбор EWMA |
| `graph.py` | Графы ближайших соседей и веса рёбер |
| `clustering.py` | Спектральные группы, согласование меток, переходы, альтернативные методы |
| `metrics.py` | SW, CH, S_Dbw, AVI, AVU, MQ и общее пространство сравнения |
| `study.py` | Исследование K и выбор по критериям 2023 |
| `economics.py` | Наблюдаемые экономические профили и перестановочная проверка |
| `pipeline.py` | Последовательность полного расчёта |
| `reporting.py` | Таблицы, массивы, графы и подробный отчёт |
| `plotting.py` | PNG и координаты графа |
| `atlas.py` | Интерактивная презентация из шаблонов |
| `config.py` | Чтение JSON и разрешение путей |

Функции документируют назначение и размерности основных входов и выходов. Проверки исходных данных предотвращают некорректные корзины и экономические значения. Проверки устойчивости — часть исследования и выбора групп.

## Настройка

Параметры находятся в [config.json](config.json). Изменение конфигурации не требует правки кода. Пути `data_dir` и `output_dir` отсчитываются от расположения JSON.

| Раздел | Что настраивается |
|---|---|
| `features` | Обучающие месяцы scaler, кандидаты α, ограничение статического baseline |
| `graph`, `clustering`, `seeds`, `random_seed` | Соседи, инициализации KMeans, фиксированные прототипы, воспроизводимость |
| `study` | Исходные K, шаг расширения и верхняя граница |
| `sensitivity` | Проверяемые месяцы, веса, соседи и шум |
| `screening` | Минимальные размеры, устойчивость, разделимость и экономические отличия |
| `economics` | Минимальное покрытие, наблюдения, описание профилей и число перестановок |
| `metrics`, `visualization`, `runtime` | Выборка SW, рисунки, координаты графа, потоки вычисления |

Фактически использованные параметры сохраняются в `notebook_results/run_config.json` вместе с фактически использованными путями. Пример: чтобы исследовать только K=2…4, задайте `study.counts: [2, 3, 4]`. Если последний вариант допустим, диапазон расширяется до `study.max_count`; для фиксированного диапазона также задайте `max_count: 4`.

## Проверка

Короткие тесты работают без исходной панели:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Полный интеграционный тест требует входных данных и заново выполняет расчёт:

```powershell
.\.venv\Scripts\python.exe -m tests.run_pipeline
```

Он сравнивает все разбиения с контрольным прогоном ноутбука до выделения модулей. Обычный запуск проекта не читает тестовые fixtures или архив.

Экономические названия описательны. Выводы относятся к полной ретроспективной выборке; занятость охватывает обследуемые организации без МСП. Более строгий порог ARI чувствительности ≥0.80 оставляет две группы. Подробности — в методологическом отчёте.
